# No1 화면 조작 없는 연결 조사

조사일: 2026-11-10 KST. 설치본: No1 Seller Center 1.35.8.

## 결론

기존 화면 조작 MCP를 대체할 실제 통신 경로가 있다. 가장 유력한 경로는 **MCP → No1 웹 원격 Relay v2 → 실행 중인 No1의 조회 핸들러 → 구조화된 결과**다. 화면 메뉴 전환·마우스·키보드 입력 없이 명령을 전달할 수 있다.

다만 **통신 경로 발견과 무팝업 실시간 검증은 별개**다. 이번 조사는 설치된 실행 코드와 공개 웹 파일만 읽었다. 로그인 정보·쿠키 저장소·`.env`를 읽지 않았고, No1 원격 명령이나 화면 조작을 실행하지 않았다. 기존 MCP의 `backgroundOnly: true`는 유지했다.

## 확인한 근거

공식 홈페이지는 PC 프로그램을 실행해 둔 뒤 같은 계정으로 모바일 웹에 접속한다고 안내한다. PC가 실제 작업을 수행하는 구조다. [공식 안내](https://onebox.team/)

공식 페이지가 안내하는 `/sourcing/` 경로에서 실제 웹 앱과 공개 설정을 확인했다.

- 웹 앱: `https://no1.certi.life/sourcing/`
- 공개 설정: `https://no1.certi.life/sourcing/config.json` — 조사 시 HTTP 200
- API: `https://relay.certi.life`
- WebSocket: `wss://relay.certi.life/ws/v2`

위 주소는 공개 웹 설정에 나온 값이며 계정 토큰이 아니다. 웹 클라이언트에는 `/app/login` 로그인 경로와 인증된 WebSocket 통신 코드가 있다. 정상적인 No1 로그인 세션을 별도로 연결해야 한다. 설치된 앱의 비밀 값을 가져오는 방식으로 구현하지 않는다.

설치본의 `RelayDispatcher`는 원격 요청을 등록된 IPC 핸들러 함수로 직접 전달한다. 개발·디버그·인증 관련 일부 명령은 원격에서 차단한다. 아래 조회 명령은 확인한 차단 규칙에 해당하지 않지만, 서버 측 계정 권한과 실제 실행 성공은 아직 시험하지 않았다.

| 대상 | 명령과 입력 | 내부 처리 및 제약 |
|---|---|---|
| 상품 재고 | `stock:check`, `{url}` | 사이트별 수집기를 직접 실행한다. 무신사 일반 요청은 Electron 세션의 `fetch`를 사용한다. |
| KREAM 시세 | `market:kream:prices`, `{productCode, size?}` | 상품번호로 가격 API를 조회한다. 로그인된 내부 브라우저 세션이 필요하다. |
| KREAM 상세 | `market:kream:details`, `{productCode}` | 상세 조회 핸들러가 존재한다. 후속 연결 시 응답 필드와 실행 분기를 검증해야 한다. |
| 무신사 혜택 | `musinsa:product:benefit`, `{productId}` | 회원 할인·쿠폰·사용 가능 적립금 관련 데이터를 조회한다. 로그인과 No1의 혜택 기준 계정이 필요하다. |
| 무신사 로그인 상태 | `musinsa:ranking:check-login`, `{}` | 로그인 상태 조회 명령이 존재한다. 세션 만료 시 무팝업 처리 검증에 사용할 후보이다. |

혜택 핸들러는 전달받은 `productId`를 사용한다. 임의로 `accountId`를 추가한다고 해당 계정으로 실행되는 계약은 아니다. 내부 세션 제공자가 선택한 혜택 기준 계정을 확인해야 한다. 응답에서 확인하지 못한 쿠폰·적립금·가격은 0으로 채우지 않는다.

## 팝업과 화면 의존 분기

1. **무신사 HTTP 조회:** `sendViaChromium`은 `session.fetch`를 호출한다. 이 통신 함수 자체에는 화면 생성이나 입력이 없다.
2. **KREAM 내부 브라우저:** 설정 `kreamApiBrowser`가 없을 때의 기본값은 `electron`이다. 내부 세션은 기본 `visible: false`, KREAM의 창 모드는 `hidden`이므로 일반 조회 경로에서 `show: false`로 생성된다. 현재 사용자의 실제 설정은 읽거나 변경하지 않았다.
3. **시스템 Chrome 분기:** `system-chrome`을 선택한 경우 `headless: false`와 화면 밖 배치를 사용한다. 이를 완전한 무팝업 실행으로 보장할 수 없다.
4. **KREAM 검색 예외:** `market:kream:search` 실패 시 `kreamSearchViaUi`로 넘어가는 분기가 있다. 최초 허용 목록에서는 제외하고 이미 확보한 상품번호로 시세를 조회하는 방식이 적합하다.
5. **무신사 재고 예외:** 내부에는 게스트 브라우저에서 장바구니를 이용하는 재고 추정 분기도 있다. 따라서 `stock:check` 전체를 순수 GET 조회라고 부를 수 없다. 상품별 실행 경로와 게스트 세션 격리를 확인해야 한다.
6. **로그인 복구와 표시 기능:** 숨겨진 재로그인, 뷰어 표시, 디버그 창 표시 코드가 각각 존재한다. 단순히 WebSocket으로 연결했다는 이유만으로 이들 분기까지 무팝업이라고 판단하지 않는다.

## 선택할 구현 방식

| 방식 | 판단 |
|---|---|
| 웹 원격 Relay를 MCP에서 직접 호출 | 우선 선택. 기존 No1 데이터·세션 처리 기능을 재사용하며 화면 조작 어댑터를 제거할 수 있다. 공식 웹 앱이 사용하는 내부 계약이므로 버전 변경 대응이 필요하다. |
| No1 공급자가 제공하는 로컬 API 또는 플러그인 | 무팝업 실행을 명시적으로 보장받을 수 있는 대안. 이번 조사에서는 공개 개발자 API 명세를 확인하지 못했다. |
| 판매처별 독립 HTTP/헤드리스 수집기 | No1 의존을 줄이는 대안. 별도 정상 인증과 데이터 검증이 필요하고, No1의 쿠폰·계정 처리 로직을 그대로 재사용할 수 없다. |

실행 파일 패치나 내부 디버그 포트 주입은 이번 조사의 선택안에 포함하지 않는다. 가상 화면에 기존 RPA를 옮기는 방식도 사용자가 요청한 화면 조작 제거와 다르다.

## 후속 구현 계약

원격 요청 형식은 `{type:"REQ", v:2, traceId, cmd, payload}`, 응답은 같은 `traceId`의 `{type:"RES", v:2, cmd, ok, data/error}`다. 연결에는 정상 로그인으로 발급된 인증이 필요하며, 토큰을 URL이나 오류 로그에 출력하지 않아야 한다.

1. 정상 인증을 주입받는 전용 Relay 클라이언트를 만든다. UI 실행 코드와 독립적으로 둔다.
2. 명령 허용 목록과 입력 스키마를 둔다. 임의 명령 실행, 창 열기, 디버그, 구매·입찰 명령을 노출하지 않는다.
3. 상품번호 기반 시세 조회부터 검증한다. 실제 KREAM 브라우저 설정과 로그인 만료 시 동작이 무팝업 조건을 만족하는지 확인한다.
4. 무신사 재고·혜택을 순서대로 붙이고 선택 계정, 상품·색상·옵션, 재고 추정 여부, 쿠폰 사용 한도, 적립금 사용액을 결과에 보존한다.
5. 조회 실패 시 화면 조작으로 자동 전환하지 않는다. 외부 클라이언트만으로 No1 내부 표시 분기를 막을 수 없다면 해당 명령은 활성화하지 않고 공급자 연동 또는 독립 조회기로 처리한다.
6. 결과 수신 시각과 원천 데이터 시각을 구분한다. 로그인 만료·데이터 부족·원격 연결 끊김은 수익 없음으로 처리하지 않는다.

## 재현 및 검증 범위

`node automation/no1-background-research/survey.mjs`는 허용된 설치 코드 파일 3개만 읽고 버전·코드 해시·기호 위치를 `static-evidence.json`에 기록한다. 설치된 코드를 실행하지 않는다. 설치본이 바뀌어 기호가 사라지면 실패한다.

`node --test automation/no1-mcp-prototype/ui-policy.test.mjs`는 기존 MCP가 UI 도구 3개를 화면 조작 전에 거절하는지 검사한다.

이번 실행 결과: 설치 코드 기호 19개 확인, 기존 UI 차단 테스트 2개 통과. 공개 Relay `/healthz`는 인증 없이 HTTP 200을 반환했다. 이 상태 응답은 계정 인증이나 상품 조회 성공을 의미하지 않는다.

2026-11-10 추가 네트워크 검증: 공개 설정 HTTP 200, Relay WebSocket 핸드셰이크 후 종료 코드 4001을 관찰했다. 설치 코드에서 4001은 인증 실패 코드로 분류된다. 인증 없는 연결에 조회 명령은 보내지 않았다. 원시 결과는 `network-verification.json`에 기록했다. UI 차단 테스트 2개도 다시 통과했다.

실시간 인증 연결 및 상품 조회는 이번 조사에서 수행하지 않았다. 따라서 이 폴더는 **연결 가능 경로와 구현 조건에 대한 조사 결과**이며 완성된 백그라운드 MCP가 아니다.
