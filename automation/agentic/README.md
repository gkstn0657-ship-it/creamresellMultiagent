# Codex CLI 에이전트 소싱

이 실행기는 AI가 검색어, 판매처, 재조회, 증거 보완, 할인 해석 및 최종 판단을 선택한다. 호스트는 허용된 도구 실행, 원문 보관, 산술, 최신성 검사, 호출 한도와 중복 방지만 담당한다. 기존 규칙 결과에 AI 의견만 붙이던 실행 방식은 `--agentic` 없는 레거시 경로에 보존했다.

## 역할과 모델

| 역할 | 모델 / 추론 | 판단 |
| --- | --- | --- |
| 조정 | gpt-6.1-sol / medium | 다음 전문 역할과 재탐색 방향 |
| 상품 목록 탐색 | gpt-6-luna / high | 목록·검색어 선택 |
| 상품 식별 | gpt-6-luna / high | 원문에 기반한 모델·색상 연결 |
| 매입처 탐색 | gpt-6.1-sol / medium | 검색어, 카탈로그, 대체 판매처 선택 |
| 쿠폰·마일리지 | gpt-6.1-sol / medium | 적용 조건·중복·계정·한도 해석 |
| 수익성 | gpt-6.1-sol / high | 옵션·수량·비용 근거 연결과 계산 요청 |
| 독립 감사 | gpt-6.1-sol / high | 증거 연결·누락·최신성·계산 검토 |

[공식 모델 안내](https://learn.chatgpt.com/docs/models?surface=cli)와 [비대화형 실행 안내](https://learn.chatgpt.com/docs/non-interactive-mode)를 바탕으로 선택했다. 현재 PC에서 Luna high와 Sol medium 실호출을 확인했고, 실제 기록 검토에서 Sol high도 사용했다. ChatGPT로 로그인된 Codex CLI를 사용하며 API 키·Claude API를 사용하지 않는다.

## 실행

프로젝트 루트에서:

```powershell
# 한 번 실행: 새 실행 폴더가 생김
.\Start-Sourcing.ps1 -Limit 5

# 하루 목표 100개를 5개씩 처리하고 24시간 간격으로 반복
.\Start-AgenticLoop.ps1

# 100개 한 주기만 실행
.\Start-AgenticLoop.ps1 -Once

# 중단 요청
.\Stop-AgenticLoop.ps1
```

`automation/loop-config.json`의 `engine`은 `agentic-codex`, `runOnce`는 `false`다. 반복 실행은 위 명령을 켠 동안 동작한다. 로그인 시 자동 시작이나 OS 작업 스케줄러 등록은 하지 않는다. STOP 파일은 자동 삭제하지 않으므로 재개 전에 내용을 확인하고 제거한다. 미완료 배치는 다음 실행에서 재시도되고 완료 배치는 보존된다.

원본을 보존하며 실제 Codex로 과거 기록을 검토하려면:

```powershell
node automation/agentic/run.mjs --out=kream-runs/my-new-review --replay-from=kream-runs/saved-batch --limit=5
```

재생에서도 AI는 실제 호출된다. 웹·No1 재조회는 금지되며 원래 관측시각을 바꾸지 않는다. 재생 결과는 현재 구매 후보로 승격되지 않는다.

## 할인과 마일리지

No1의 표시 혜택 내역을 항목별로 분해해 정상가에서 할인·사용 적립금을 뺀 금액이 표시 결제금액과 일치하는지 검사한다. 최대혜택가는 탐색용 추정이다. 개인 쿠폰·결제수단·잔액·잔여 한도·실제 결제금액이 확인되지 않으면 확정하지 않는다.

기존 적립금 사용은 현금 지출과 경제적 비용을 분리한다. 예를 들어 현금 8만원과 적립금 1만원을 사용하면 경제적 매입비용은 9만원이다. 신규 적립은 별도로 표시하며 미확인 적립을 이익에 더하지 않는다. 여러 개 구매에는 해당 수량의 할인 후 상품 합계·현금 결제액·적립금 사용 원문을 요구하며, 현금과 적립금 합계가 상품 합계와 맞아야 한다. 1개용 쿠폰을 수량만큼 복제하지 않는다. `record_batch_conditions`로 수량별 배송비·구매 제한·동일 옵션 거래 원문과 보수적 판매 수량 가정을 기록한다. 판매 수량은 확정 수요가 아니며 관측된 거래 표본 이상으로 부풀릴 수 없다.

No1 혜택은 조회한 색상·옵션별로 별도 저장한다. `L(100)`과 KREAM `L`처럼 표기가 다르면 자동으로 같은 옵션이라고 가정하지 않는다. 정해진 인용 형식으로 결제 금액을 확인하지 못하면 보류하고 원문을 남긴다.

## 관찰과 복구

- `agentic-state.json`: 단계, 재개 상태, 호출 수, 오류, 중복 방지 기록.
- `agent-decisions/`: 각 역할의 입력, 결정, 실제 모델·추론·토큰 사용.
- `agent-tool-results/`, `observations/`: 도구 결과와 원본 보관.
- `margin-screen.json`, `benefit-scenarios.json`: 옵션별 가능성과 할인 계산.
- `agentic-final.json`, `automation-report.html`, `automation-final.xlsx`: 감사 결과.

AI는 JSON으로만 허용된 도구를 요청한다. 임의 셸·파일 경로·새로운 미관측 판매처 링크를 실행할 수 없다. 원문 인용은 실제 파일과 대조하며 No1 최대혜택가는 실결제가 증거로 사용할 수 없다. 주문·입찰·쿠폰 사용·계정 변경 도구는 제공하지 않는다.

`config.json`은 에이전트 호출·도구·페이지·No1 조회·재시도 한도를 정한다. 한도, 반복 정체, STOP는 `needs_attention` 또는 `stopped`로 표시한다. 감사가 외부 장애 때문에 보류로 끝나면 미해결 원인을 함께 기록한다. 상품을 하나도 확보하지 못한 실행은 완료 처리하지 않는다. 만료된 네트워크 관측은 중복 방지를 풀어 다시 조회할 수 있다. 최종 제출과 배치 집계 때 가격·재고·시세 최신성을 다시 검사한다. 합산 결과는 기존 Dot 승인 파일 대신 이 실행기의 독립 Codex 감사 결과를 확인한다. 실행 `complete`는 검토가 끝났다는 뜻이며, 모든 상품이 구매 후보라는 뜻은 아니다.

## 실시간 실행 조건

Chrome에 `naver-extension`이 로드되고 실행 상태여야 페이지 수집이 가능하다. 로컬 릴레이는 `Start-Relay.ps1`로 실행한다. 사용자의 No1 팝업 금지 요청에 따라 현재 No1 연결은 `--background-only`이며 화면 조작 호출을 차단한다. 비화면 실시간 조회 연결은 아직 구현되지 않았고, 에이전트에도 이 상태를 전달해 No1 재시도를 피한다. 기존 No1 자료는 원래 관측시각을 유지하며 최신 근거로 대체하지 않는다.

```powershell
node --test automation/agentic/agentic.test.mjs
```

## 이번 구현 검증 기록

2026-11-09에 회귀 테스트 159개를 통과했다. 실제 Codex CLI 기록 재생은 9회 호출로, 새 실시간 상품 탐색은 15회 호출로 독립 감사까지 완료했다. 실시간 실행 중 발견한 `1.S(90)` 형식의 옵션 인용 결함은 수정한 뒤 같은 AI 결정과 원본으로 재시험하여 S·M·L·XL·XXL 다섯 가격 근거가 모두 저장되는 것을 확인했다. 미확인 재고·혜택 조건은 그대로 보류된다.

이후 사용자가 화면을 열어준 상태에서는 시세 조회가 성공했다. 재고 결과도 화면에 도착했지만 무신사 로그인이 없어 혜택 정보가 숨겨져 있었다. 이를 전체 조회 시간 초과로 오인하던 처리는 수정하고 단위 테스트했다. 사용자의 후속 팝업 금지 요청 이후 실시간 화면 시험은 중단했고, MCP 프로세스 수준에서 세 UI 도구 모두 차단되는 것을 검증했다. 비화면 실시간 조회는 별도 연결이 필요하다. 연속 루프는 아직 상주 실행하지 않았다. [검증 상세와 코드 해시](../../kream-runs/agentic-build-20261109/validation.json)에 테스트·실제 호출·남은 제약을 구분해서 기록했다.

팝업 금지와 로그인 필요 상태 처리를 포함한 최종 회귀 테스트는 164개 통과했다.
