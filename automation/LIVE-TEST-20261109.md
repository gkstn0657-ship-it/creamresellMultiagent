이번 실행은 실제 사이트에서 목록→KREAM→네이버→판매처→판정→보고서가 이어짐을 확인했다. 수익성 있는 동일 옵션을 찾은 실행은 아니므로 후보 승격 및 No1 교차 검증의 실전 통과는 확인되지 않았다. 하루 500개 처리량도 아직 검증되지 않았다.

## Dot 직접 실행 검증

기존 `내 dot`에 메인 커맨더 책임을 전달하고 연결된 PC에서 `doctor`·`status`·`smoke`를 직접 실행하게 했다. Dot의 [새 실전 실행](../kream-runs/live-smoke-20261109T063618)은 KREAM 목록 50개 ID 중 3개를 분석했고, 최종 후보 0·보류 0·제외 3이었다. Dot이 생성한 [HTML](../kream-runs/live-smoke-20261109T063618/automation-report.html)과 [엑셀](../kream-runs/live-smoke-20261109T063618/automation-final.xlsx)을 확인했다. Dot 환경의 Codex CLI 경로 탐색을 보강한 뒤 `doctor`에서 `codexSignedIn: true`를 확인했다.

Dot이 `start`로 일일 500개 루프를 시작했다. 20개 목록 소스에서 [고유 상품 ID 500개](../kream-runs/automation/2026-11-09-cycle-01/k50-ids.json)를 확보했다. 이어 500개 KREAM 페이지를 모두 수집한 뒤 네이버를 처리하면 초반 관측값의 10분 유효기간이 지나므로, 일괄 실행을 `STOP`으로 중단했다. ID는 보존하고 5개씩 독립 처리하도록 수정해 [cycle-02](../kream-runs/automation/2026-11-09-cycle-02)에서 재개했다. 첫 배치는 수집→네이버→판매처→감사→HTML·엑셀을 약 2분 30초에 완료했고 [상위 보고서](../kream-runs/automation/2026-11-09-cycle-02/automation-report.html)에 상품 5개 모두 제외로 집계됐다. 전체 500개 완료는 아직 진행 중이다. Dot의 매일 09:00 KST 점검 예약에 후보·보류 독립 스크리닝도 추가했다.

Dot이 [첫 배치의 독립 스크리닝](../kream-runs/automation/2026-11-09-cycle-02/dot-screening-batch-001.json)을 직접 기록했다. 원본 근거 21개를 대조해 5개 모두 승인 없이 보류/제외 유지로 판단했다. 이 과정에서 네이버 검색 카드 상위 3개를 **상품 일치 필터보다 먼저 자르던 탐색 누락**을 발견했다. `parse-si.mjs`를 전체 카드에서 모델·브랜드·국내 판매 일치 여부를 먼저 확인하고 유효 카드 3개를 선택하도록 수정했다. 실제 저장된 덤프를 다시 해석하자 Alo 모델 U3040RG의 5번째 카드가 포착됐다. 동일 옵션 재고·판매자·결제가가 없으므로 후보로 승격하지 않았다. KREAM 자기 재판매 카드는 소싱 후보에서 제외했다.
