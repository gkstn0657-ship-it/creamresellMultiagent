# 순차 순환 탐색 계획 — 2026-11-10

사용자가 요청한 N개 범위만 실행한다. 탐색 단계는 고정 코드이며 LLM을 호출하지 않는다. 기존 상품별 수익성 담당과 독립 검토 AI는 유지한다.

1. No1의 조회 전용 인기순 목록을 페이지 단위로 읽는다. 전체 목록 경로의 실제 동작은 별도로 검증한다. 원천 순위는 인기순이며 최근 30일 실거래 순위라고 표현하지 않는다.
2. 상품 이름의 명시적 규칙으로 신발·의류·잡화·뷰티·테크·생활취미·기타·미분류 대기열에 넣는다. 명칭 기반 분류는 미검증 라벨이며 모호한 상품은 미분류로 남겨 누락하지 않는다. 공식 분류 필드가 연결되면 이를 우선 사용하도록 별도 버전으로 전환한다.
3. 준비된 각 대기열에서 한 상품씩 순환한다. 목록 원천 순서를 보존한다. 다음 카테고리, 원천 커서, 미처리 목록, 배치 예약은 SQLite에 저장한다. 실제 시장 전체의 완전 수집을 주장하지 않는다.
4. 새 작업에서도 저장된 위치부터 이어간다. 동일 KREAM ID는 중복 배정하지 않는다. 모든 관측 목록을 소진하면 임의로 기존 상품을 재실행하지 않고 소진 상태를 알린다. 페이지 실패는 빈 목록이나 완료로 바꾸지 않는다.
5. 후보별 구매처를 고정 규칙으로 조회하고 모델·색상·옵션 일치를 검증한다. 현재 혜택 수집이 지원되는 구매처는 무신사다. 지원하지 않는 구매처·불명확한 매칭·미확인 비용은 자료 부족으로 보존하고 적자 판정으로 바꾸지 않는다.
6. 최대 5개 후보의 자료를 먼저 모두 묶은 후 기존 상품 AI를 동시 2개까지 실행한다. 후보 ID 단위로 N개를 계산하며 조회 실패·보류도 별도로 보고한다. 자동으로 목표 수량을 늘리지 않는다.
7. PC의 고정 실행 루프가 해당 작업의 남은 배치를 계속 실행한다. Dot은 시작·상태 확인·중단을 담당하고 완료 이벤트로 결과를 읽는다. 실행 중인 순환 작업에 별도 배치를 중복 추가할 수 없게 한다.

검증: 여러 작업에 걸친 순환 위치 유지, 중복 ID·페이지 중복·커서 루프, 재시작 후 같은 예약 재사용, 조회 오류 시 진행 보존, N개 초과 방지, 중단·재개, 미확인 상품의 부분 자료 전달, 실제 인기 목록과 실상품 조회를 각각 검증한다. No1 창 조작·표시 및 주문 실행은 사용하지 않는다.

## 적용·검증 결과

- 인기순 원천 목록 50개와 다음 페이지 커서를 실제 조회했다. 목록 수준 사전 읽기는 N개 상세 조사 수량에 포함하지 않는다.
- 격리된 실검증에서 목록 순환기가 어그 타스만 2 슬리퍼(574093)를 자동 선택하고 실제 시세·거래 근거를 수집했다. 상품 담당·독립 검토를 마쳤으며 매입처 미확인으로 보류했다. 전체 150건 관측은 불완전 수집의 하한이며 확정 30일 거래량이나 수익이 아니다.
- 사용자 작업 3개 후 새 작업 4개로 위치 이어가기, 7개를 5+2로 실행, 중단·재개, 기존 수동 작업 완료 상품 중복 방지, 준비 단계 오류 알림을 검증했다. 이 순환 검증은 합성 데이터 시험이다.
- Dot MCP 0.5.0을 배포하고 보호된 진단 경로에서 새 도구 및 PC 상태 왕복을 확인했다. 실제 Dot 대화가 새 탐색 도구를 선택해 시작하는 동작은 아직 별도 확인 대상이다.
- 운영 작업은 생성하지 않았다. 새 N개 지시를 기다리는 상태다. 관리 UI 표시는 이번 범위에 포함하지 않았다.
