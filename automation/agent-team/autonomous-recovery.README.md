# 상품 판단 자동 복구

상품 담당자가 턴을 마쳤는데 유효한 assessment가 없으면 사용자의 재지시를 기다리지 않고 오류 도구·코드, 원자료와 검수 기록을 포함한 복구 턴을 시작한다. 기존 상품 범위에서 최대 2회 수행하며, 낮은 모델은 기존 1회 승격 한도 안에서 Sol/high로 인계한다. 에이전트가 원인을 진단하고 원자료 재확인, 제안 수정, 재검수, 결과 저장을 수행한다. 복구 턴마다 독립 검수 호출은 최대 3회이며 기존 실행의 도구 예산은 초기화하지 않는다.

검수 요청의 원안을 검수자 actor와 review에 저장한다. `publish_reviewed_assessment(reviewId)`는 그 원안을 기존 publishAssessment 검증에 그대로 전달한다. 원문 재작성에 따른 proposal hash 불일치를 방지하면서 독립 pass·동일 근거·동일 원안·담당자 권한 검증을 유지한다. 과거 review에 원안이 없으면 새 검수를 요청해야 한다. rework를 pass로 바꾸거나 검증을 우회하지 않는다.

STOP이면 추가 복구 턴을 실행하지 않는다. 2회로 해결하지 못하면 needs_attention으로 남고 기존 연속 감독기가 저장 작업을 다시 시도한다. 타임아웃·접속 장애는 기존 종료/재개 경로로 전달한다. 이 기능은 범용 코드 자동 수정기나 로그인 복구기가 아니다. PC 종료, 감독 프로세스 자체의 종료, 외부 인증 요구 등 모든 장애를 해결한다고 보장하지 않는다.

검증: `node --test automation/agent-team/autonomous-recovery.test.mjs`. 원안 변조·오래된 근거·rework 거절, 실제 호스트 도구를 통한 저장, 모델 인계, 복구 상한과 STOP을 검사한다.
