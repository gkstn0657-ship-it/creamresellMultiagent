# 탐색 상태 감시와 AI 장애 진단

2026-11-11 사용자 요청: 상품 탐색과 독립된 상시 감시 구현. 후속 지시로 구현만 먼저 하고, 현재 상품 탐색이 끝난 뒤 테스트한다.

## 동작

- `health-monitor.mjs`: 10초마다 작업 상태, 실행기, 로컬 연결 상태와 최근 수집/AI 판단 기록의 갱신 시각을 읽는다. 유한 수량 작업과 연속 작업을 지원한다.
- 상품 수가 잠시 그대로여도 상품별 AI 기록이 갱신되면 진행 중으로 본다. 수집 5분 / 상품 판단 10분 동안 기록 갱신이 없으면 지연으로 기록한다.
- 오류 원문 대신 고정 오류 코드와 최소 상태 메타데이터를 AI에 전달한다. 정상 폴링은 모델을 호출하지 않는다.
- 지속되는 오류는 최소 2회 관찰 후 한 번 진단한다. AI 호출 간격은 15분 이상, 최대 시간당 4회이며 호출 이력은 재시작 후에도 유지한다. 모델은 기존 research 설정인 `gpt-6-luna/medium`이다.
- AI에는 진단 기록 도구 하나만 제공한다. 파일/코드 수정, 상품 조회, UI, 로그인, 구매, 재시작을 수행하지 않는다. 기존 coordinator/commander의 복구 정책과 탐색 커서에 관여하지 않는다.
- 상태: 해당 작업의 `health-monitor.json`, AI 근거/결과: `health-diagnostics/<incident-id>/`. 대시보드 서버를 다음에 재시작하면 별도 감시 상태를 노출한다.
- 현재 작업이 정상 완료되거나 사용자가 중지하면 감시 프로세스도 종료된다. Windows 재부팅 후 자동 시작은 설치하지 않는다.

## 테스트 시점

`verify-health-monitor-after-work.mjs`는 현재 작업이 `complete`이고 기존 상품 실행기들이 종료된 것을 확인하기 전에는 테스트나 모델을 실행하지 않는다. 중간 오류는 완료로 취급하지 않고 복구를 기다린다. 명시적 작업 중지는 테스트 예약을 취소한다.

완료 후 관련 단위/회귀 테스트를 실행하고, 통과하면 합성 장애 한 건으로 실제 Codex 모델의 읽기 전용 진단 도구 호출을 확인한다. 이 모델 테스트는 실제 상품 장애의 해결을 입증하지 않는다. 테스트 결과는 `health-monitor-validation.json`과 `health-monitor-tests.log`에 저장한다. 테스트가 끝나도 감시기를 자동 활성화하지 않는다.

```powershell
node automation/agent-team/verify-health-monitor-after-work.mjs --root=<agent-teams 절대경로> --work=<기존 work ID>
```

검증 후 필요한 작업에 감시기를 연결한다. 이미 살아 있는 동일 감시기가 있으면 중복 실행하지 않는다.

```powershell
node automation/agent-team/health-monitor.mjs --root=<agent-teams 절대경로> --work=<기존 work ID> --attach
```

감시만 중지하려면 해당 작업 디렉터리에 `HEALTH_MONITOR_STOP` 파일을 만든다. 상품 탐색 중지 파일 `STOP`과 분리되어 있다.

기존 정책은 그대로다: `358dfb7`의 연속 탐색 조회 실패 1초/1회 재시도 후 건너뛰기, `0c6c339`의 인증·전송·스키마 오류 분류. 감시 AI의 문장은 권고일 뿐 복구 명령으로 해석하거나 실행하지 않는다.
