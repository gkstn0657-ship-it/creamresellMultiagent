# 탐색 감시 오류 코드

이 숫자는 No1/KREAM의 HTTP 응답값이 아니라 탐색 내부 신호다. 전체 오류 이름과 담당 작업의 단일 원본은 [`error-catalog.mjs`](./error-catalog.mjs)이다. No1 확장에 공개된 오류 이름과 기존 실수집 로그의 사유를 테스트에서 대조한다.

| 코드 | 뜻 | 조율자 배정 및 처리 |
| --- | --- | --- |
| 200 | 정상·사용자 중지·다음 인기 순위 주기 대기 | 커맨더가 현 상태 유지. 사용자 중지는 재시작하지 않음 |
| 210 | 재고 없음 또는 재고 옵션의 양수 마진 없음 | 상품 판정 기록. 탐색 장애로 취급하지 않음 |
| 211 | 동일 모델·옵션 연결 실패, 형식/상품 정보 불일치 | 상품 제외 사유 기록. 다른 상품으로 계속 |
| 212 | 이미 확인한 KREAM 상품 | 중복 제외 기록. 저장된 순위·카테고리 위치 유지 |
| 400 | 잘못된 응답·스키마·패킷·설정 변경 | 진단 기록. 자료를 임의 보정하지 않음 |
| 401 | No1·무신사·KREAM 로그인/토큰 만료 또는 Dot 브리지 인증 실패 | 인증/원격 브리지 담당. 필요한 인증 상태만 기록, 자동 로그인 없음 |
| 403 | 허용되지 않은 명령·백그라운드 모드 위반 | 진단 기록. 화면 조작으로 우회하지 않음 |
| 404 | 인증된 No1 웹 탭 없음/접근 불가 | 브라우저 연결 담당. 백그라운드 상태를 읽고 복구되면 저장 요청 재시도 |
| 409 | 실행기 중복 실행·작업 충돌 | 진단 기록. 중복 프로세스를 만들지 않음 |
| 426 | 확장 버전 불일치 | 확장 담당. 새 버전 필요 상태 알림 |
| 429 | 요청 제한·유지 보수·브리지 사용 중 | 속도 담당. 기존 대기·재시도 간격 준수 |
| 500 | 탐색 실행기 종료 | 실행 담당. 열린 연속 작업일 때만 제한 간격으로 재시작 |
| 501 | 아직 분류되지 않은 오류 | 진단 담당. 원래 사유를 보존해 기록하고 분류 보강 대상으로 남김 |
| 502 | KREAM 검색·재고·랭킹·혜택 등 원본 조회 실패 | 원본 담당. 같은 상품과 저장된 요청을 보존하고 정해진 재시도 사용 |
| 503 | 확장·릴레이 연결 끊김 또는 로컬/원격 브리지 불가 | 연결/브리지 담당. 연결 복귀 대기 또는 로컬 브리지 제한 재시작 |
| 504 | 명령 시간 초과 또는 진행 정체 | 지연 담당. 정체 진단 기록, 상품을 처리 완료로 표시하지 않음 |

모니터는 10초 주기로 No1/작업 신호와 Dot 원격 브리지 신호를 별도 채널에 저장한다. 조율자는 숫자를 그대로 믿지 않고 오류 사유로 코드를 다시 계산해 수신 확인을 쓴다. 커맨더는 그 확인의 담당 작업을 실행하고 결과를 기록한다. 새 오류 이름은 501로 처리되므로 정상 200으로 숨지 않는다. 인증이나 확장 연결이 필요한 상태는 자동 화면 제어를 하지 않는다.
