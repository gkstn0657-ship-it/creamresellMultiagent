# No1 마진 결과 연결

## 최신 변경: 실제 시세표 스키마 수집 (2026-11-10)

Connector 0.6.0은 No1의 `market:kream:history:start`와 상품·작업 ID가 일치하는 PUSH를 받아 사이즈별 30일 집계, 원본 집계 방식, 신뢰도, 완료 상태, 기준 시각을 보존한다. 상세 가격 조회의 `includeFastDelivery:true`로 빠른배송 가격도 요청한다. 실제 없는 가격은 null이다. 아래 초기 구현의 '보판 미수집'과 '기본 수수료만 사용'은 새 `marketSchemas` 경로에는 적용되지 않는다.

- `team_state.marketSchemas`, `read_market_schema`, 새 배치 결과, `cream_batch_status`, `cream_panel_data`에 표 전체를 연결했다. 상품 담당·검증 에이전트가 이 근거를 우선 읽는다.
- `no1_displayed_value`: 이미 열린 동일 상품의 웹 시세표에서 직접 읽은 선택 판매 방식의 마진금·표시 수익률. 화면 입력 매입가·희망가·수수료·부가세·이벤트 적용 여부도 함께 읽는다. 화면을 열거나 조작하지 않는다.
- `no1_formula_with_observed_inputs`: 수집한 매입가와 실제 저장된 웹 수수료 설정을 적용한 계산값. 화면 표시값이라고 주장하지 않는다. 화면이 닫혀 있으면 미입력 희망가를 만들지 않는다.
- No1 `estimated` 집계는 예상 거래량이며, 완전하게 수집된 실제 거래내역 건수(`actualRecordedTrades30d`)와 별개다. 부분 집계·오류·다른 작업의 PUSH·사이즈 충돌은 확정 수치로 취급하지 않는다. 합계는 표의 사이즈 행을 합산하며 누적 거래량으로 대체하지 않는다.
- 표의 실제 원본 데이터와 설정을 읽을 수 없는 이전 관측은 그 한계를 유지한다. 기존 `margins`는 이전 기본 조건의 계산이며 새 스키마와 구분한다. 수수료 이벤트를 조회하지 않은 사이즈는 일치 검증이 안 된 계산값이다.
- 기존 수집 캐시의 유효기간은 5분이다. 재사용 시 원래 관측 시각을 보존하며 실시간 재조회로 표시하지 않는다.

### 실제 검증 및 종료 상태

2026-11-10 18:00:59 KST, 로그인된 Chrome 확장 0.6.0 → No1 공식 Relay → No1의 단건 수집부터 CLI 스키마 출력까지 성공했다. 검증 상품은 KREAM 1120286 / NBNPG41033 BLACK / 무신사 7481180이다.

| 집계 방식·상태 | raw / final, 캐시 상태 fresh |

위 마진은 수집 조건으로 계산한 값이다. 해당 상품의 웹 시세표가 열려 있지 않아 직접 표시값 비교는 하지 못했다. 사용자가 작업 종료를 요청해 추가 조회·화면 대조를 중단했다. 원본 표시값 추출은 합성된 production VNode·DOM 테스트로만 검증됐다. 데스크톱 앱의 별도 설정까지 읽었다고 주장하지 않는다. 원격 호스팅 패널 화면 변경은 이번 범위에 포함하지 않았다.

관련 자동 테스트 160개 통과. 실제 수신 자료는 로컬 `kream-runs/no1-schema-live/probe/observation.json`과 `schema.json`에 보관하며 계정 원문·인증 비밀·공개 사이트 번들은 커밋하지 않는다. 이전의 다중 로그인 세션 오류는 사용자의 탭 정리 후 해소됐다.

## 초기 마진 계산 구현 기록

상품 수집 자료에서 사이즈별 `마진금 (수익률)`을 계산해 에이전트와 MCP에 제공한다. 추가 네트워크 조회나 AI 호출 없이 계산한다. 마진금의 부호로 `남음 / 손해 / 본전`을 구분하고, 필수 자료가 없으면 `계산 불가`를 반환한다. 15% 등 임계값은 사용하지 않는다.

- `team_state.margins`: 기본 조건의 마진 결과.
- `read_margin_report({desiredSellingPrice?, taxMode?, fees?})`: 담당·검증 에이전트의 읽기 전용 계산 도구. 지정 옵션은 계산에만 적용하며 실제 No1 설정을 바꾸지 않는다.
- `cream_batch_status({runId}).margins`: 기존 MCP 도구에 상품별 결과를 추가한다.
- `cream_panel_data({runId})`: 모델이 읽는 텍스트 결과와 패널 데이터의 상품별 `margins`에 같은 결과를 포함한다.
- 새 배치 결과와 최종 평가에 기본 조건 결과를 저장한다. 기존 저장 원자료도 조회 시 계산하며, 과거 관측을 최신 조회로 표시하지 않는다.

각 행은 판매 방식, 매입가, 판매가, 마진금, 수익률, 수수료 근거, 재고, 원자료 ID, 관측 시각, 자료 부족 이유를 포함한다. AI의 채택·보류·제외 판단과 산술 결과는 별개다.

## 계산 조건

매입가는 일치하는 상품·옵션에서 수집한 No1 `maxBenefitPrice` 원금액을 사용한다. 반올림된 할인율로 재계산하지 않는다. 이 금액은 실제 결제 확정가가 아니다. 다른 사이즈의 높은 가격을 대입하지 않는다. 예전 자료에 `sizeBinding`이 없으면 유일하게 일치하는 사이즈 표기만 연결한다. 신발 국가별 사이즈 환산은 추정하지 않는다.

현재 연결은 KREAM 일판(`buyPrice`)·즉판(`sellPrice`) 가격을 제공한다. 보판은 가격 미수집으로 계산 불가이며, 희망 판매가는 명시적으로 입력했을 때만 계산한다. POIZON 산술 함수는 검증했지만 POIZON 시세 자동 수집은 포함하지 않는다.

사용자별 No1 설정을 읽었다고 가정하지 않는다. 기본 KREAM 수수료는 6% + 검수비 2,500원, 부가세 모드는 OFF다. 정확히 일치하는 상품·옵션·가격·판매 방식의 수수료 이벤트 미리보기가 있으면 해당 값을 적용한다. 별도 `fees` 지정도 가능하다. 배송비·추가 비용·실제 체결을 확정하지 않으므로 결과는 해당 계산 조건의 예상 마진이다.

## 검증과 운영

`node --test automation/agent-team/*.test.mjs`로 산술·자료 매칭·누락·오래된 관측·에이전트·MCP 전달을 검증한다. `node automation/agent-team/panel-ui/verify-margins.mjs`는 격리된 headless Edge에서 실제 패널 빌드와 MCP Apps 연결을 합성 자료로 검증한다. No1 UI나 실제 AI 작업은 실행하지 않는다.

관리 패널 소스에는 마진 표를 추가했다. 로컬 패널 빌드와 호스팅된 패널 배포는 별개이며, 원격 MCP의 데이터 응답은 PC 브리지 코드 재시작으로 반영된다.

이번 확인에서 No1 인증 요청은 `NO1_MULTIPLE_WEB_SESSIONS`를 반환했다. 따라서 새 실시간 시세 수집부터 결과까지의 검증은 미완료다. 저장 자료 조회와 합성 자료 검증을 실시간 검증으로 취급하지 않는다.
