# 박한수 에이전트 작업방식

이 문서에서 사용자가 바꾼 작업방식을 관리한다. 제임스는 작업을 시작할 때 해당 기준을 적용하고, 검토자와 감사총무는 같은 기준으로 결과를 확인한다. 같은 주제에 대한 요청이 바뀌면 요청 시각이 가장 최근인 지시를 따른다. 변경이 구현됐는지는 실제 결과로 별도 확인한다.

## 현재 기준

- **업무 담당** — 실무자 이름은 제임스다. 반복되는 분류·대조·정리·변환이 있으면 먼저 범위와 검수 기준을 정한다. 맡기는 편이 효율적일 때만 경량 계약직을 쓰고, 결과는 제임스가 원본과 대조한다. 직접 처리하는 편이 나은 일은 제임스가 처리한다. 일상적인 조회·집계·파일 정리·진행 보고는 제임스가 검수하고 마감한다.
- **클레어와 모건** — 검토자 클레어(Claire)가 일반 장애·중지·복구 기록을 감사한다. 감사총무 모건(Morgan)은 제임스의 작업 상황을 상시 관찰하고, 여러 업무에 영향을 주는 오류·데이터 무결성 훼손·반복 복구 실패 등 핵심 사안에 개입한다. 단순 결과의 건별 검토는 생략한다. 수익 후보 채택 전 상품 단위 독립 검증은 소싱 파이프라인에서 수행한다.
- **실행과 보고** — PC의 백그라운드 CLI에서 실행한다. 한 데스크톱 창의 오른쪽 통합 채팅에 요청과 진행 상황을 요약하고, 사용자 원문을 보존한다. 중앙 원의 움직임은 실제 작업 단계와 병행 실행 상태를 반영한다. 에이전트는 공유 기록으로 인계하고, 복구 가능한 기존 소싱 작업은 기존 작업 번호와 범위에서 재개한다.
- **모델 호출과 토큰** — 네이버에서 확인할 항목이 없는 역할은 ‘대상 없음’으로 기록한다. 원자료 누락은 따로 표시하고, 성과 검토는 수익 후보·실제 거래·재검 기한 도래 때 실행한다. KREAM에서 일치하는 매입 옵션과 견적이 모두 없고 추가 시세 수집이 유보된 상품은 담당자와 독립 검토자가 각각 보류에 동의해야 종결한다. 수익 가능성이 있거나 판단이 엇갈리면 원문으로 독립 검토한다. 팀보드는 사용자 요청과 새 근거를 인계하고 반복 진행 기록은 요약한다. [역할별 토큰 집계](../automation/team-board/token_report.py)에서 입력·캐시 입력·출력·추론을 확인하고, 계측되지 않은 값은 미확인으로 남긴다.
- **창 정리** — 에이전트가 작업용으로 연 창과 탭은 사용을 마치면 닫는다. 인계나 후속 작업에 필요한 창은 마지막 담당자가 다 쓴 뒤 닫는다. 사용자가 열어 둔 창이나 계속 띄워 달라고 한 대시보드는 유지한다.
- **모션 원** — 입자 구체의 중심을 고정하고 바깥 둘레의 주황색 선만 제거한다. 구체 안의 연결선과 기존 다른 색 궤도선은 유지한다. 진행 중인 고유 업무 한 건마다 점 모양 위성 하나가 주위를 공전한다. 업무가 종료되면 해당 위성을 없애고, 진행 중인 업무가 없으면 위성도 표시하지 않는다.
- **KREAM 후보** — No1 인기 목록의 저장 위치에서 이어간다. 카테고리 안의 원래 순위와 카테고리 순환 순서를 유지하고, 이전 배정 ID를 건너뛴다. 분류가 모호하면 미분류에 남긴다. 인기순·누적 판매량과 최근 사이즈별 체결량을 구분한다.
- **무신사 후보** — No1의 카테고리·기간·성별·연령을 읽고 해당 랭킹의 1위부터 순서대로 조사한다. 전체 카테고리에서 수익 후보를 계속 찾을 때는 종합 다음 고정 하위 카테고리로 진행한다. KREAM 인기순과 진행 위치·중복 이력을 분리한다. KREAM과 POIZON을 각각 조회하고 근거와 비용을 따로 남긴다.
- **네이버 매입처 검색** — KREAM 후보의 품번을 네이버 가격비교에서 낮은 가격순으로 검색한다. 추천 낮은 가격순을 해제하고 첫 세 자리를 본다. 해외직구나 모델·색상 불일치가 있어도 네 번째 카드로 대체하지 않는다. 일치하는 국내 상품의 판매처 상세에서 옵션·재고·판매자·배송비와 혜택을 확인한다. 엑셀은 동일 모델의 옵션별 값을 같은 행에 모은다.
- **수익 판단** — 판매량을 우선하고 동일 모델·색상·사이즈의 실제 재고를 기준으로 판단한다. 판매처에서 확인된 쿠폰, 최소 구매액·할인 상한, 결제수단·회원·기간 등 적용 조건과 배송비를 기록한다. 실제 적용이 확인된 할인으로 매입가를 계산한다. 판매가에서 매입가·배송비·판매 수수료·적용 세금 등 비용을 뺀 현금 순이익과, 지급 근거가 있는 신규 적립을 포함한 예상 이익을 따로 표시한다. 최대 혜택·조건 미확인은 조건부로 기록한다. 이미 할인된 가격과 중복 쿠폰, 기존 적립금 사용과 신규 적립을 구분한다.
- **판매처·검토** — SSG·G마켓·29CM·솔드아웃·네이버스토어 등 입점몰의 신뢰도를 고려하고, 실제 판매 주체와 해당 옵션 증거를 함께 본다. 최근 사이즈별 체결가·거래량을 호가와 구분한다. 재고·비용·거래 근거가 부족하면 보류하고, 조회 실패·확인된 적자는 따로 기록한다. 조사 수와 독립 검토를 통과한 수익 후보 수를 구분한다.
- **조사 종료** — ‘상품 N개 조사’는 보류·조회 실패를 포함해 서로 다른 상품 N개를 확인하면 종료한다. ‘수익 후보 N개 찾기’는 같은 옵션의 실재고, 양수 마진, 최근 사이즈별 거래 근거와 독립 검토를 통과한 고유 상품만 센다. 양쪽 플랫폼에서 통과해도 한 개로 세고, 랭킹이 소진되면 확보 수와 남은 수를 보고한다. 같은 상품을 혜택 확인 목적으로 다시 조회하면 기존 조사 건에 연결한다.
- **보고 항목** — 날짜별 보고에 상품명·모델·옵션·구매처·매입가와 배송비, 판매 플랫폼·판매 방식별 예상 판매가·순이익·마진율, 최근 거래 근거, 최종 판단과 출처를 남긴다. 중단·복구 알림은 대시보드에 표시하고 감사총무에게도 전달한다. 담당자가 조치 결과를 공유 채팅에 요약한다.
- **저장과 개인 취향** — 소싱 결과는 한국 날짜 기준 `상품탐색결과/YYYY-MM/YYYY-MM-DD.md`에 저장한다. 브리핑은 현재 대시보드에서 제거하고 구현과 하트 보관함, 개인 취향 기록은 복원할 수 있도록 보관한다. 개인 자산, 계정, 인증 정보는 이 작업방식 문서에 적지 않는다.

실제 확인에 로그인이 필요하면 판매처와 확인 항목을 사용자에게 알린다. 사용자가 확인해 준 계정 이용 조건은 개인 프로필에서 관리한다. No1은 시세 비교와 무신사 랭킹 분석을 백그라운드로 조회한다.

## 변경 이력

- **2026-11-07 · 네이버 소싱** — 낮은 가격순의 첫 세 자리, 판매처 배송비를 포함한 마진, 적립 포함 수익 별도 표기, 옵션별 결과 한 행 정리를 적용한다.
- **2026-11-22 · 담당·혜택** — 실무자 이름을 제임스로 정했다. 판매처 상세의 적립금·할인쿠폰·적용 조건을 확인해 수익성 판단에 반영한다.
- **2026-11-22 · 변경 관리** — 이후 작업방식 수정은 여기에 요청 날짜와 변경 내용을 남기고 다음 작업부터 참고한다. 일회성 업무 수량이나 상태 질문은 해당 업무 채팅에 보관한다.
- **2026-11-22 · 반복 업무와 검토 범위** — 제임스가 알바에게 맡길 만한 반복 작업이 있는지 확인하고 필요할 때만 고용한다. 일상 결과는 제임스가 마감한다. 검토자는 오류·중지 기록을 관리하고 중요한 시스템 장애에 개입한다.
- **2026-11-22 · 브리핑 보관** — 글귀·시와 AI 뉴스 각 세 개 및 스크롤, 하트 저장과 추천, 뉴스 출처·발표일 표시 구현을 보관하고 화면에서는 제거한다.
- **2026-11-22 · 창 정리** — 작업용 창과 탭은 사용이 끝나는 즉시 닫는다.
- **2026-11-22 · 원의 움직임** — 원 전체가 위아래로 떠다니는 효과를 제거한다.
- **2026-11-22 · 감사 분담** — 클레어가 평상시 감사를 맡고, 모건은 제임스를 관찰하다 핵심 사안을 맡는다.
- **2026-11-22 · 원의 선 제거 범위 정정** — 사용자가 화면 예시에서 지정한 대상은 바깥 주황색 선이다. 내부 연결선과 다른 궤도선은 유지한다.
- **2026-11-22 · 작업 수 표시** — 진행 중인 작업 수와 공전하는 점 모양 위성 수를 일치시킨다.
- **2026-11-22 · 토큰 사용 최적화** — 네이버 빈 호출과 팀보드의 중복 인계를 줄이고 역할별 사용량을 기록한다. 수익 후보 채택 전 독립 검토를 유지한다.
- **2026-11-22 · 다른 PC 이전** — 하나의 Git 복제본에서 대시보드·CLI·소싱 도구를 실행한다. 작업 원장·취향·탐색 위치와 중단 상태는 개인 이전 파일로 보존한다. 복원과 점검을 마친 뒤 운영할 PC 한 곳에서 기존 작업 번호를 재개한다. [2026-11-22 Windows 이전 안내](2026-11-22-windows-handoff.md)
