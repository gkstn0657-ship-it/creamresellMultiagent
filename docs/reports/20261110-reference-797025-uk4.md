## 기준 수립에 반영할 사항

1. 수익성 평가와 구매 가능성을 분리한다. 매물 부재는 구매 불가 사유이며, 과거에 통과했던 수익성 사례를 곧바로 손실 사례로 재분류할 근거가 아니다.
2. 평가 단위는 품번·색상·사이즈·판매 방식이다. 상품 전체 최저가와 다른 사이즈의 거래량을 섞지 않는다.
3. No1 표시 수익률과 매입원가 대비 수익률을 혼동하지 않는다. 현재 코드의 No1 계산은 판매가(부가세 모드에서는 세전 판매가)를 분모로 사용한다. 화면 선택 방식과 세금 설정도 함께 보존한다.
4. 마진율과 원 단위 이익을 같이 본다. 거래량·최근 체결 분포·호가 깊이·판매 방식·매입부터 판매까지의 기간을 함께 검토해야 하며, 이 사례 한 건으로 최소 수익률이나 최소 거래량 임계값을 확정하지 않는다.
5. 화면 입력 매입가는 실제 구매 가능한 가격이라는 보장이 없다. 재고 없음·할인 종료·쿠폰 자격 미확인은 각각 표시한다. 기존 적립금 소모와 신규 적립도 구분한다.
6. 참고 사례 채택, 원자료의 산술 검증, 구매 가능, 실제 수익 실현은 서로 다른 상태다. 사용자 평가를 모델 검증 완료로 바꾸지 않는다.

## 연결 구현과 검증 상태

최신 레포의 Connector 0.6.0에는 `market:kream:displayed-schema`가 이미 구현돼 있다.
기존 상품 probe는 무신사 URL·옵션·재고 확인을 먼저 요구하므로, 품절 참고 사례용으로
`no1_background_displayed_schema({kreamId:"797025"})`를 로컬 No1 MCP에 추가했다.
이미 열린 동일 상품 시세표만 읽으며 화면 열기·클릭·탐색·재고조회·구매를 수행하지 않는다.
반환된 `data.inputs`, `data.rows`, `data.asOfText`를 함께 검토한다.
`displayedValueVerified`는 표 원본 읽기 성공일 뿐 수익성 또는 재고 검증이 아니다.

초기 원본 조회는 `NO1_CONNECTOR_UPDATE_REQUIRED`로 차단됐다. 브리지의
`observedConnectorVersion`과 `requiredConnectorVersion`으로 연결 확장의 버전을 구분하도록 보완했다.
사용자 재연결 후 실제 `browserConnected:true`, `observedConnectorVersion:0.6.0`을 확인했다.
원본 표 MCP는 실행됐으나 `available:false / MATCHING_PRICE_TABLE_NOT_OPEN`을 반환했다.
별도 실시간 호가 요청은 `NO1_PLATFORM_LOGIN_REQUIRED`로 차단됐다.
따라서 원본 UK4 마진금·수익률은 아직 미확인이다. 새 도구의 원문 보존·다른 상품 차단·품절 조회 독립성은
합성 데이터 및 MCP 등록 테스트로 검증했으며 이 결과가 실제 표 조회를 대신하지 않는다.

실제 조회가 성공하면 원자료는 Git 제외 경로 `kream-runs/reference-797025/`에 저장하고,
위 미확인 상태를 실제 입력 조건과 수치로 보완한다. 런타임 상품 선택·탐색 커서·판단 임계값은 변경하지 않는다.

구현 검증: 상품팀·No1 연결·원본 표 MCP·기존 UI 차단 및 MCP 목록 검사를 포함해 **180개 테스트 통과**.
브리지 설정 조회에서 electron 모드·혜택 계정 설정 존재는 실제 확인했다.
이 진단 성공이나 합성 표 테스트를 UK4 원본 마진 검증으로 표시하지 않는다.
