# 무신사 3개 중심 기준 적용

사용자 요청: 무신사 탐색의 판단을 마진율·재고·최근 판매동향 중심으로 변경.

## 실행 구조

1. No1에 선택된 카테고리/기간/성별/연령으로 인기순 후보 조회: 고정 로직, 탐색 AI 없음.
2. 이미 연결된 KREAM 상품과 구매처 옵션의 자료 수집/계산: 코드.
3. `cream_musinsa_batch_start`: 기존 사용자 확인 N 작업 범위 내에서 `musinsa-ranking` 프로필을 저장하고 실행·재개. 일반 배치와 프로필을 혼동하거나 같은 요청 ID로 바꾸면 실패한다.
4. 상품 담당 AI: 판매 방식별 마진율, 옵션 재고, 최근 거래량/가격 흐름으로 adopt/hold/exclude 판단.
5. 독립 검증 AI: 원자료와 저장된 계산 근거를 확인하고 게시. 기존 모델과 검증 역할은 유지한다.

첫 판단에서는 추가 수집·조사 도구를 제공하지 않으며 실행 측에서도 거부한다. 임의의 하위 조사 에이전트도 비활성화한다. 일반 탐색 정책·커서·N 범위·일반 판단 프로필은 그대로다. 새 통과 마진율·최소 거래량 임계값을 임의로 추가하지 않았다.

## 판단 자료

- 판매 방식별 마진금/마진율과 실제 관측 매입가·수수료 조건. 직접 표시값과 산식 계산값 구분.
- 구매 옵션의 재고·구매 가능 여부. 0과 미확인 구분.
- 해당 시장 사이즈의 30일 추정 거래량 및 집계 시각. 실제 체결과 별도 표시.
- 저장 거래 조회 종료 시각 기준 최근 7일과 직전 7일의 실제 관측 건수·중앙 거래가격. 완전한 14일 수집 범위일 때만 증가/감소·가격 변화를 표현한다. 선택 옵션 연결이 없으면 시장 참고값으로만 남긴다.
- 계산은 `musinsa_screening_signals` 관측 레코드에 원자료 ID·집계식·원래 시각을 함께 저장한다. 검증자는 계산 근거를 직접 읽으며 숫자를 다시 추측할 필요가 없다.

## 검증

- 관련 전체 검사 202개 통과. 기간 경계, 사이즈 분리, 불완전·오류 자료, 재고 0/미확인, 최근 수집 실패, N 제한, 일반/무신사 프로필 분리·재개, 저장 계산 근거, 실제 팀 생성 시 도구 제한을 검사했다.
- 기존 토트백 패킷(무신사 2235274/KREAM 후보 107609)을 replay로 표시해 실제 상품 AI·독립 검증을 실행했다. 새 상품 조회 및 N 추가 소비 없음.
- 저장 집계: ONE SIZE 최근 7일 29건/중앙가 96,000원, 직전 7일 16건/100,000원. 구매처 NONE과 연결 미확인인 시장 참고값.
- 최종 replay 실행: 45.113초, hold, 독립 검증 pass 1회. 도구 기록에 collect_no1/investigate 없음. 이 시간은 저장 자료 판단 시간이며 새 상품 탐색부터 분석 완료까지의 실시간 성능 수치가 아니다.
- 첫 replay에서는 검증자가 동향 계산의 별도 근거를 요구해, 계산 레코드 저장을 보완하고 다시 실행했다.

## 적용 범위

레포의 실행 코드·CLI 프로필·MCP 도구 정의·Dot 도구 빌드 정의에 반영했다. 이미 가동 중인 외부 MCP/클라우드 서비스 재시작·재배포는 이번 검증에 포함하지 않았다. 새 도구가 아직 노출되지 않는 세션은 최신 checkout의 `control('cream_musinsa_batch_start', args, {root: 기존 작업 기록 경로})`로 동일 경로를 실행할 수 있다.

랭킹 후보의 KREAM 자동매칭과 랭킹 전용 N개 연속 실행 루프는 이 변경에 포함되지 않는다. 이미 연결된 후보에 적용하는 판단 경로이며, 이를 완전 자동 탐색 완료로 표현하지 않는다.
