# 마지막 검토(위험등급·근거) — AI에게 맡기는 단계

> 2026-11-08: 아래는 과거 수동 절차다. 현재 run-all의 최종 감사는 `agents-audit.mjs`로 통합됐으며, 추가 AI 감사는 `--agents-llm`(GPT-6.1 Sol High)을 사용한다. 새 흐름은 `AGENTS-README.md`를 따른다. 과거 상품명 기반 `risk-ai.json`은 옵션별 승인 근거로 사용하지 않는다.

run-all 이 엑셀까지 만든 뒤, "후보*" 와 "사람 검토" 행의 **위험등급(낮음/중간/높음)** 과 **위험근거** 를 AI 가 쓴다.
점수 합산 규칙은 코드(build-final-today.mjs 의 RISK_RULE)와 같고, 항목별 점수와 문장은 AI 가 판단한다.
2026-11-06 에는 Opus 서브에이전트로 돌렸다(39행, 약 11만 토큰, 3.5분).

## Claude Code 에서 실행하는 법
1. 이 폴더(Cream)에서 Claude Code 를 연다.
2. 아래 프롬프트의 `<run-dir>` 을 실제 폴더(예: kream-runs/20261107)로 바꿔 보낸다. 모델은 Opus 권장(근거 문장 품질), 비용을 아끼면 Sonnet 중간.
3. 결과 `risk-ai.json` 이 생기면 `node kream-tools/build-final-auto.mjs <run-dir>` 와 `python -I kream-tools/export-xlsx.py <run-dir>/final-all.json <run-dir>/result.xlsx` 를 다시 돌리면 엑셀의 위험등급·위험근거 열이 채워진다(크림ID+상품명으로 합침).

## 프롬프트 (그대로 복사)
```
<run-dir>/final-all.json 의 rows 중 판정이 '후보'로 시작하거나 '사람 검토'인 행에 위험등급과 위험근거를 써줘.
규칙: kream-tools/build-final-today.mjs 1~60줄의 RISK_RULE, risk(), 항목별 helper 를 읽고 같은 7항목 점수표(0 양호/1 주의/2 위험, 합계 0~3 낮음, 4~7 중간, 8+ 높음)를 적용.
근거는 행의 필드(차트 분류/판단/근거, 최근30일 체결, 시세기준, 예상순수익, 수익률, 판매처, 상호명, 대표자, 사업자구분, 재고확인, 리스크, 사유)로 쓰고, 필요하면 같은 폴더의 dump-K<크림ID>.json, dump-N<크림ID>-prod.json, facts.json 을 읽어도 됨. 웹은 보지 말 것.
정직성: 증거가 없는 항목(재고 미확인 등)은 2점으로 두고 그렇게 적을 것. 사실을 지어내지 말 것. 크림 상품명과 판매처 제목의 색상·모델이 다르면 반드시 지적할 것. 마진이 아주 크면(30% 이상) 시세가 오래된 것인지 마지막 체결일을 확인해 적을 것.
형식: 항목마다 한 줄 "이모지(🟢0 🟡1 🔴2) 항목명: 짧은 근거 (N점)", 그 다음 "☞ 확인: 사람이 무엇을 확인하면 등급이 바뀌는지", 마지막 줄 "▶ 합계 N점 → 위험 등급". 한 행 700자 이내, 한국어.
출력: <run-dir>/risk-ai.json 에 [{"크림ID","상품명"(행과 정확히 같게),"위험등급","위험근거"}] 배열로 저장. 다른 파일은 수정하지 말 것.
끝나면 등급별 개수와, 데이터 품질에서 발견한 가장 중요한 문제 3가지만 짧게 보고.
```

## 어제(2026-11-06) 이 단계가 잡아낸 것
- 유일한 후보가 크림은 블랙, 판매처 제목은 네이비였고 재고 있는 S 사이즈로 다시 계산하면 마진 2.4% → 후보에서 제외. 이후 색상 대조 규칙을 build-final-auto 에 추가.
- 마진 87.6% 상품의 마지막 체결이 394일 전 → 시세가 오래됨.
- 판매처 제목에 "하자" 표기, 한 사이즈 매입가를 다른 사이즈에 적용한 행, 다른 판매처보다 36% 싼 단일 매물 등.
